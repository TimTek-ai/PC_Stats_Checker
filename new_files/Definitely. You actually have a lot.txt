## What I'd learn now

### 1. 🧠 Understand LLMs properly

Don't go deep into the maths yet. Get a practical mental model of:

* tokens
* context windows
* temperature
* system/user/assistant messages
* embeddings
* inference
* quantisation
* parameters
* attention
* transformers
* hallucinations
* tool calling

You should be able to explain:

> **"What actually happens when I send a prompt to an LLM?"**

without just saying "it predicts the next word."

---

### 2. 🔎 Learn RAG — I'd make this your #1 topic

This is probably the most valuable thing to start learning.

Understand this pipeline:

```text
Documents
    ↓
Extract text
    ↓
Chunk documents
    ↓
Create embeddings
    ↓
Store embeddings
    ↓
User asks question
    ↓
Embed question
    ↓
Vector similarity search
    ↓
Retrieve relevant chunks
    ↓
Put chunks into context
    ↓
LLM generates answer
```

Learn these concepts individually:

**Embeddings → vector databases → cosine similarity → chunking → retrieval → reranking → context windows → grounding**

You don't need to build the entire thing yet.

---

### 3. 🗄️ Learn pgvector

Since you've already worked with PostgreSQL/TimescaleDB, this should be relatively easy.

Understand:

* what a vector column is
* how embeddings are stored
* cosine similarity
* nearest-neighbour search
* indexes
* metadata filtering
* hybrid search

Eventually you'll be able to write something conceptually like:

```sql
SELECT *
FROM documents
ORDER BY embedding <=> query_embedding
LIMIT 5;
```

and actually understand what that is doing.

---

### 4. 📊 Start thinking about evaluation

This is where I'd have you go beyond the average beginner.

Learn:

> **How do you prove an AI system is actually better?**

For example, imagine:

**RAG v1**

* 70% retrieval accuracy
* 78% answer accuracy

Then you change chunking.

**RAG v2**

* 86% retrieval accuracy
* 89% answer accuracy

That's meaningful engineering.

Look into concepts like:

* precision
* recall
* F1
* retrieval accuracy
* faithfulness
* answer relevance
* hallucination detection
* benchmark datasets

You don't need to master every metric yet.

---

# 5. 🤖 Learn what fine-tuning actually does

Before touching MLX-LM, understand the distinction:

### Prompting

```text
Model
+
Instructions
=
Different behaviour
```

### RAG

```text
Model
+
External information
=
Grounded answers
```

### Fine-tuning

```text
Model weights
+
Training examples
=
Changed model behaviour
```

Then learn:

**LoRA**

and

**QLoRA**

You should understand why LoRA is useful rather than just knowing that it's "a fine-tuning method."
