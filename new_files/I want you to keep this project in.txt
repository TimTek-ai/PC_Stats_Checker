## Core goal

I want to build a serious, open-source AI research assistant rather than a generic "ChatGPT clone."

The long-term system should combine:

1. Prompting/persona/system-prompt engineering
2. RAG (retrieval-augmented generation)
3. PostgreSQL + pgvector
4. Quantitative evaluation/benchmarking
5. Fine-tuning small open models with LoRA/QLoRA
6. Apple Silicon / MLX for local experimentation
7. Cloud NVIDIA GPUs such as RunPod/Colab for heavier training
8. A polished GitHub repository, documentation and demo
9. Eventually potentially a hosted version / premium features
10. Potential sponsorships, cloud credits, competitions, grants or funding

The goal is to build something genuinely technically impressive and potentially commercially useful, not just something that looks good in a portfolio.

## Planned progression

### Phase 1 — Prompting and persona design

I want to learn how to deliberately control an AI assistant using:

* system prompts
* context
* instructions
* tool definitions
* structured outputs
* memory/state
* prompt testing
* evaluation

I want to avoid simply writing an enormous prompt and calling it done.

The aim is to understand why certain instructions produce better behaviour and measure improvements.

### Phase 2 — RAG

Build a proper retrieval-augmented generation pipeline.

Likely architecture:

Python
→ document ingestion
→ chunking
→ embeddings
→ PostgreSQL + pgvector
→ retrieval
→ possibly reranking
→ context construction
→ LLM
→ cited/grounded response

I already have experience with PostgreSQL/TimescaleDB from another project, so PostgreSQL + pgvector is probably preferable to introducing Chroma unless there is a good reason to use Chroma.

Potential knowledge sources:

* research papers
* technical documentation
* project documentation
* my own notes
* public datasets
* eventually financial/quant research

The system should answer questions based on retrieved sources rather than simply relying on the model's pretrained knowledge.

### Phase 3 — Evaluation

This is extremely important.

I want a proper evaluation dataset, initially perhaps 50–200 questions, measuring things such as:

* retrieval accuracy
* relevance of retrieved chunks
* answer correctness
* hallucination rate
* citation/source accuracy
* latency
* token usage/cost

The point is to be able to compare:

Prompt A vs Prompt B
Retriever v1 vs Retriever v2
Model A vs Model B
Base model vs fine-tuned model

I want the project to demonstrate actual engineering and experimentation rather than subjective "this response feels better."

### Phase 4 — Fine-tuning

After understanding RAG and evaluation, I want to learn the complete fine-tuning pipeline.

Use:

* LoRA
* QLoRA
* small open-weight models
* MLX/MLX-LM on Apple Silicon for local experimentation
* RunPod/Colab/NVIDIA cloud GPUs for workloads that are too heavy for the Mac

Important distinction:

RAG is mainly for giving the model access to external/up-to-date/domain-specific knowledge.

Fine-tuning is mainly for changing behaviour, style, task performance or domain adaptation.

Don't recommend fine-tuning simply because it sounds more advanced if RAG is the correct solution.
